Hugo로 기술 블로그를 운영하는 방법

2026년 5월 26일 · 2 분

이 블로그는 Hugo, PaperMod, GitHub Pages를 사용해서 운영한다. 글은 Markdown으로 작성하고, Hugo가 정적 HTML 파일로 변환한 뒤 GitHub Pages가 그 결과물을 웹사이트로 보여주는 방식이다.

Hugo는 무엇인가#

Hugo는 정적 사이트 생성기다. 서버에서 매번 페이지를 만드는 대신, 미리 HTML 파일을 만들어 둔다. 그래서 블로그처럼 글 중심의 사이트를 빠르고 단순하게 운영하기 좋다.

이 블로그에서는 역할이 나뉘어 있다.

  • jimin-blog: 글, 설정, 테마가 들어 있는 Hugo 소스 저장소
  • Yundimin.github.io: Hugo가 만든 HTML 결과물을 배포하는 GitHub Pages 저장소
  • themes/PaperMod: 블로그 디자인을 담당하는 PaperMod 테마 submodule
  • public: 배포 저장소를 연결한 submodule

새 글 작성하기#

새 글은 content/posts 아래에 Markdown 파일로 만든다.

cd /Users/jimin/projects/yeardream/jimin-blog
hugo new content posts/my-new-post.md

생성된 파일의 앞부분에는 front matter가 들어간다.

+++
title = '글 제목'
date = 2026-05-26T21:45:00+09:00
draft = false
+++

draft = true이면 초안이라 일반 빌드에 포함되지 않는다. 실제 배포할 글은 draft = false로 바꾼다.

로컬에서 확인하기#

글을 작성하면서 바로 확인하려면 Hugo 서버를 실행한다.

hugo server --buildDrafts

브라우저에서 http://127.0.0.1:1313/ 또는 http://localhost:1313/로 접속하면 로컬 미리보기를 볼 수 있다. 파일을 수정하면 Hugo가 자동으로 다시 빌드한다.

배포용 HTML 만들기#

배포 전에는 정적 파일을 만든다.

hugo

이 명령은 결과물을 public 폴더에 만든다. 이 블로그에서는 public이 Yundimin.github.io 저장소와 연결되어 있어서, 이 폴더 안의 변경 사항을 push하면 GitHub Pages 배포 대상이 된다.

배포 흐름#

글을 작성하고 배포할 때의 흐름은 다음과 같다.

cd /Users/jimin/projects/yeardream/jimin-blog
hugo

cd public
git add .
git commit -m "Deploy new post"
git push

cd ..
git add content/posts/my-new-post.md public
git commit -m "Add new Hugo post"
git push

먼저 public 저장소에 빌드 결과를 올리고, 그 다음 jimin-blog 저장소에 글 원본과 public submodule 포인터를 기록한다.

기억할 점#

Hugo 블로그에서 가장 중요한 원칙은 원본과 결과물을 구분하는 것이다. 글과 설정은 jimin-blog에 남기고, 실제 웹사이트 파일은 Yundimin.github.io에 배포한다.

이 구조를 지키면 글 작성, 테마 관리, 배포 이력을 각각 명확하게 관리할 수 있다.
